## 1. The Problem

### What are Audio Deepfakes?
An **audio deepfake** is a synthetic voice recording generated by an AI system — specifically a Text-to-Speech (TTS) or Voice Conversion (VC) model. These systems have become remarkably good. Without a trained ear, it is essentially impossible for a human to tell the difference.

Our project's goal is to build a binary classifier:
- Input: An audio clip (`.wav`, `.mp3`, etc.)
- Output: A single number between 0 and 1 (a **probability**)
  - Close to **0** → Real human speech
  - Close to **1** → AI-generated / Deepfake speech

### Why is this hard?
The difficulty is that modern TTS systems (like the ones in your dataset — xTTS, OpenAI, VALLE, etc.) don't leave obvious, audible artifacts. The differences between real and fake are often:
- Subtle unnatural **frequency distributions** in certain bands
- Missing or over-smoothed **micro-variations** in pitch
- Inconsistent **temporal patterns** (real speech is slightly jittery in a natural way; TTS is too smooth)
- Artifacts at the **spectrogram** level that are invisible in a waveform

The key insight: **the raw audio waveform is not the best representation for classification.** We need to transform it into a 2D image-like representation that exposes these subtle patterns. That transformation is called a **spectrogram**.

## 2. Sound as Data

### What is a sound wave?
When you speak, you create pressure waves in air. A microphone converts these pressure fluctuations into an **electrical signal**, which is then digitally sampled at a fixed rate.

### Sample Rate
Your project uses `SAMPLE_RATE = 16000` Hz (16 kHz). This means:
- The microphone measures the audio signal **16,000 times per second**.
- Each measurement is one **sample** — a single floating point number representing air pressure at that moment.
- A 3-second clip = `3 × 16,000 = 48,000` raw numbers.

```
Raw audio waveform (1D array):
[-0.012, 0.034, 0.056, -0.023, 0.019, ...]
  t=0ms   t=0.0625ms  ...
```

The **Nyquist Theorem** tells us a sample rate of 16 kHz can faithfully capture frequencies up to 8 kHz, which covers all human speech frequencies (typically 80 Hz – 8000 Hz).

### Why not just feed the raw waveform to a CNN?
You could, but it's extremely inefficient. A 3-second clip at 16 kHz is a 48,000-point 1D signal. Finding a subtle artifact at, say, 4.2 kHz requires the network to somehow discover that relationship on its own from raw samples. It is much better to pre-compute a **frequency-vs-time map** (a spectrogram) and let the CNN find spatial patterns in that 2D image.

## 3. Feature Engineering: Spectrograms

A spectrogram is a 2D matrix where:
- **X-axis** = Time (each column is a short time window)
- **Y-axis** = Frequency (each row is a frequency band)
- **Pixel value** = Energy (how loud is that frequency at that moment)

There are two types used in this project.

### 3.1 Short-Time Fourier Transform (STFT) → Linear Spectrogram

The core operation is the **Fourier Transform (FFT)**, which decomposes any signal into a sum of sine waves. For audio, this tells you "at this moment in time, how much energy exists at each frequency?"

Since audio changes over time, we can't just FFT the entire clip at once. Instead, we use the **Short-Time Fourier Transform (STFT)**:
1. **Slide a window** of length `N_FFT = 512` samples across the audio.
2. Move the window by `HOP_LENGTH = 256` samples at a time (~16ms steps).
3. Apply FFT to each window.
4. Stack all the FFT outputs side-by-side.

```
Audio:  [==============================...]  (48,000 samples)
         [  window  ]                         FFT → 257 frequencies
              [  window  ]                    FFT → 257 frequencies
                   [  window  ]               FFT → ...

Resulting 2D matrix shape: (257, 192)
   257 = N_FFT // 2 + 1 = unique frequency bins
   192 = number of time steps = ceil(48000 / 256)
```

The 257 frequency bins are **linearly spaced** from 0 Hz to 8000 Hz. Each bin is `8000 / 257 ≈ 31 Hz` wide. This gives equal weight to every frequency band.

In code (`audio_preprocessing.py`):
```python
linear_spec = np.abs(librosa.stft(audio, n_fft=N_FFT, hop_length=HOP_LENGTH, window="hann")) ** 2
```
- `np.abs(...)` → magnitude of complex FFT output
- `** 2` → power spectrum (energy = amplitude²)
- `window="hann"` → a tapered window to reduce FFT edge artifacts

### 3.2 Mel Spectrogram

The **Mel scale** is a perceptual frequency scale that mimics how the human ear works:
- Human hearing is **logarithmic** — we're more sensitive to differences in low frequencies than high frequencies.
- Going from 100 Hz to 200 Hz sounds like the same "step" as going from 1000 Hz to 2000 Hz.

A Mel filterbank takes the linear spectrogram and **groups frequency bins** using triangular filters spaced on the Mel scale. Your project uses `N_MELS = 64` filters, so the output shape is `(64, 192)`.

```
Linear Spectrogram (257, 192)
         ↓ 64 triangular Mel filters
Mel Spectrogram (64, 192)
```

Low-frequency bins get narrow filters (fine resolution), high-frequency bins get wide filters (coarse resolution). This matches human perception.

In code:
```python
mel_spec = librosa.feature.melspectrogram(y=audio, sr=16000, n_mels=64, n_fft=512, hop_length=256)
```

### 3.3 Converting to Decibels (log scale)
Both spectrograms are then converted to the **dB scale**:
```python
mel_db = librosa.power_to_db(mel_spec, ref=np.max)
```
This applies `10 × log10(power / ref)`, resulting in values from roughly -80 dB (silence) to 0 dB (peak). This is important because:
1. Energy values span many orders of magnitude (10⁻⁶ to 10³). Log scale compresses this range.
2. Neural networks train much more stably on well-scaled inputs.

### 3.4 Z-Score Normalization
Finally, each spectrogram is normalized per-sample:
```python
spec = (spec - spec.mean()) / (spec.std() + 1e-6)
```
This makes the mean ≈ 0 and standard deviation ≈ 1. The `1e-6` prevents division by zero for silent clips. This ensures no single clip dominates training due to scale differences.

## 4. Dual-Frontend Strategy: Why Two Spectrograms?

This is the core design philosophy of your project. Instead of feeding one spectrogram to the model, you feed **both** simultaneously, with two parallel processing branches.

| Feature | Mel Spectrogram | Linear (STFT) Spectrogram |
|---|---|---|
| Shape | `(64, 192, 1)` | `(257, 192, 1)` |
| Frequency bins | 64 (perceptual) | 257 (physical) |
| Frequency scale | Logarithmic (Mel) | Linear (Hz) |
| Resolution at low freq | High | Low |
| Resolution at high freq | Low | High |
| What it captures well | Phoneme/speech patterns | Fine harmonic structure, TTS artifacts |

**The intuition:**
- TTS models often fail to perfectly replicate **low-frequency prosodic patterns** (natural speech rhythm, intonation) → Mel spectrogram catches this.
- TTS models often leave **harmonic artifacts** at specific high-frequency bands → Linear spectrogram catches this.
- By using both, the network has access to complementary information and can form a more complete judgment.

Think of it like having two doctors examine an X-ray: one expert in soft tissue, another in bone structure. Their combined diagnosis is more reliable than either alone.

## 6. The Preprocessing Pipeline

Every audio file goes through this exact sequence:

```
Raw file (.wav/.mp3)
      │
      ▼
librosa.load(sr=16000, mono=True)        → Loads at 16kHz, converts stereo→mono
      │
      ▼
pad_or_trim_audio()                       → Exactly 48,000 samples (3 seconds)
      │                                    Short clips: zero-pad at the end
      │                                    Long clips: truncate at 3 seconds
      ▼
librosa.feature.melspectrogram()          → Shape: (64, ~188) raw
librosa.stft()  |  np.abs() ** 2         → Shape: (257, ~188) raw
      │
      ▼
librosa.power_to_db()                     → Convert to dB scale
      │
      ▼
fix_time_steps()                          → Pad/crop to exactly 192 time steps
      │
      ▼
normalize_spec()                          → Z-score: (x - mean) / std
np.expand_dims(axis=-1)                   → Add channel dim: (64,192,1), (257,192,1)
      │
      ▼
{"mel_input": (64,192,1), "linear_input": (257,192,1)}
```

### Why 3 seconds?
This is our **speed optimization**. The original code used 10 seconds. The tradeoff:
- **10 seconds** → richer temporal context, but `MAX_TIME_STEPS = 320`, large feature maps, slow.
- **3 seconds** → covers 2–3 phonemes/words, enough for pattern detection, `MAX_TIME_STEPS = 192`, ~3x faster.

For most TTS artifacts (harmonic inconsistencies, unnatural smoothness), 3 seconds is more than sufficient to detect them.

### The `tf.data` Pipeline: Why It Matters
The dataset is not loaded all into RAM at once (that would require ~50 GB). Instead, `create_dataset()` builds a lazy pipeline:

```python
ds = tf.data.Dataset.from_tensor_slices((paths, labels))  # just lists of paths
   .shuffle(buffer_size=3557)                              # randomize order
   .map(tf_parse_audio, num_parallel_calls=AUTOTUNE)       # load+preprocess in parallel
   .batch(64)                                              # group into batches
   .prefetch(AUTOTUNE)                                     # prepare next batch in background
```

Key concepts:
- **`shuffle`**: Randomizes order so the model doesn't learn "first half are fakes". `buffer_size = len(paths)` means full shuffle (best quality).
- **`num_parallel_calls=AUTOTUNE`**: TensorFlow automatically decides how many CPU cores to use for loading files in parallel. This is why training uses all CPU cores.
- **`prefetch`**: While the GPU is training on batch N, the CPU is already loading and preprocessing batch N+1. Eliminates idle time.
- **`BATCH_SIZE = 64`**: 64 samples per gradient update step.

## 7. Model 1 — The Baseline CNN

### Architecture Overview

```
mel_input (64,192,1)        linear_input (257,192,1)
     │                              │
     ▼                              ▼
[Conv2D 32] → [BN] → [MaxPool]   [Conv2D 32] → [BN] → [MaxPool]
     │                              │
[Conv2D 64] → [BN] → [MaxPool]   [Conv2D 64] → [BN] → [MaxPool]
     │                              │
[Conv2D 128] → [BN] → [MaxPool]  [Conv2D 128] → [BN] → [MaxPool]
     │                              │
[Conv2D 256] → [BN]              [Conv2D 256] → [BN]
     │                              │
[GlobalAvgPool] → (256,)        [GlobalAvgPool] → (256,)
     │                              │
     └────────── Concatenate ───────┘
                     │
                  (512,)
                     │
              [Dense 256] → [Dropout 0.4]
                     │
              [Dense 128] → [Dropout 0.3]
                     │
              [Dense 1, sigmoid]
                     │
              fake_probability ∈ (0, 1)
```

**Total params: ~943K**

### What Each Layer Actually Does

#### `Conv2D(32, (3,3), padding='same', activation='relu')`
A 2D convolution slides a **3×3 filter** (kernel) across the spectrogram. The filter learns to detect local patterns like edges, ridges, or blobs in the frequency-time space.
- `32` = number of different filters (each detects a different pattern)
- `padding='same'` = output has same width/height as input (zero-pad edges)
- `activation='relu'` = ReLU(x) = max(0, x) — squashes negatives, keeps positives. This introduces non-linearity.

In a spectrogram context, Conv2D filters learn things like:
- Horizontal edges = sudden energy change at a particular frequency
- Vertical edges = sudden onset or offset of sound
- Diagonal patterns = frequency sweeps (formants in speech)

#### `BatchNormalization`
After each Conv2D, before activation, we normalize each feature map across the batch. This:
- Stabilizes training (reduces internal covariate shift)
- Acts as a mild regularizer
- Allows higher learning rates
- Practically: it makes training ~2x faster and more reliable

#### `MaxPooling2D((2,2))`
Reduces spatial dimensions by half (takes max value in each 2×2 block). After 3 MaxPool layers:
- Mel branch: `(64,192)` → `(32,96)` → `(16,48)` → `(8,24)`
- Linear branch: `(257,192)` → `(128,96)` → `(64,48)` → `(32,24)`

MaxPool achieves two things:
1. **Translation invariance**: If an artifact is slightly shifted in time or frequency, it still gets detected.
2. **Receptive field expansion**: The effective area of the input seen by deeper filters grows.

#### `GlobalAveragePooling2D`
Reduces the entire remaining feature map to a single vector by averaging all spatial positions. A `(8,24,256)` feature map becomes `(256,)`. This produces a **global descriptor** of the clip regardless of clip length.

#### `Concatenate`
Merges mel features `(256,)` and linear features `(256,)` into `(512,)`. This is the **fusion point** — from here, the Dense layers see information from both spectrograms simultaneously.

#### `Dense` + `Dropout`
Standard MLP layers for final classification. `Dropout(0.4)` randomly zeros out 40% of neurons during training — this is regularization that prevents overfitting by making the network redundant.

#### `Dense(1, sigmoid)`
Output layer. Sigmoid maps any real number to `(0, 1)`. This value is the predicted **probability of being fake**.

### The Increasing Filter Count Pattern (32 → 64 → 128 → 256)
This is a fundamental CNN design principle:
- Early layers: fewer filters, detect simple patterns (edges)
- Later layers: more filters, detect complex patterns (combinations of edges)
- As spatial resolution decreases (pooling), we compensate by increasing depth
- This keeps the total information capacity approximately constant throughout the network

## 8. Model 2 — The Flagship: BiCrossMamba-ST

This is your more sophisticated model (`bicrossmamba_st/model.py`). It uses ideas from three cutting-edge research areas: **State Space Models (Mamba)**, **Cross-Attention**, and **Spectro-Temporal tokenization**.

### The High-Level Intuition

The CNN treats the spectrogram as a plain image and extracts local features. The BiCrossMamba-ST model instead:
1. Looks at the spectrogram as a collection of **frequency bands** (spectral tokens) AND **time intervals** (temporal tokens) simultaneously.
2. Processes each sequence with **bidirectional state-space scans** to capture long-range dependencies.
3. Uses **cross-attention** to let the spectral stream "ask questions" of the temporal stream and vice versa.
4. Fuses all three perspectives (spectral, temporal, raw map) for final classification.

### Step-by-Step Data Flow

#### Step 1: Input Normalization & Fusion
```python
mel  → Resize to (128, 192, 1)    # bilinear interpolation
linear → Resize to (128, 192, 1)  # both now same spatial size
x = Concatenate([mel, linear])    # shape: (128, 192, 2)
```
Both spectrograms are resized to the same dimensions so they can be concatenated channel-wise. This gives every subsequent layer access to both frequency representations.

#### Step 2: Conv Stem — Extracting a Joint Feature Map
```python
x → Conv2D(48, 5x5) → BN → Conv2D(96, 3x3) → BN → SpectroTemporalAttention → AveragePool(2,4)
```
Output shape: `(64, 48, 96)` — this is the **shared feature map** (`d_model=96` channels).

**SpectroTemporalAttention2D** is a lightweight self-attention mechanism:
- Two convolutions: one `(5,1)` (tall, frequency-focused), one `(1,7)` (wide, time-focused)
- They produce an attention map (values 0–1) via sigmoid
- Applied as `output = input × (1 + attention)` — multiplicative gating
- This highlights the most discriminative regions of the feature map before tokenization

#### Step 3: Dual Tokenization
This is the key innovation. From the same `(64, 48, 96)` feature map, we create two different sequence views:

**SpectralSubBandTokenizer:**
```
Feature map: (batch, 64 freq, 48 time, 96 channels)
→ Split freq into 8 bands of 8 bins each
→ Average within each band: (batch, 8 bands, 48 time, 96)
→ Reshape to sequence: (batch, 8×48=384, 96)
```
Each token in this sequence represents "what's happening in this frequency band at this time step."

**TemporalIntervalTokenizer:**
```
Feature map: (batch, 64 freq, 48 time, 96 channels)
→ Split time into 8 intervals of 6 steps each
→ Average within each interval: (batch, 64 freq, 8 intervals, 96)
→ Reshape to sequence: (batch, 8×64=512, 96)
```
Each token represents "what's happening at this frequency across this time interval."

**Why two views?** They encode complementary structure:
- Spectral tokens excel at detecting **which frequencies** are anomalous.
- Temporal tokens excel at detecting **when** patterns change unnaturally.

#### Step 4: BiMambaBlock — Bidirectional Selective State Space Model

This is the `Mamba`-inspired core. Classical RNNs (like LSTMs) process sequences step by step, which is slow and struggles with very long-range dependencies. Mamba uses a **Selective State Space Model (SSM)** that:
1. Maintains a **hidden state** that summarizes past context
2. Uses **input-dependent** forget/update gates (`alpha`) — the network learns to selectively remember or forget
3. Can be computed efficiently in parallel (unlike traditional RNNs)

The recurrence equation:
```
state[t] = alpha[t] × state[t-1] + (1 - alpha[t]) × candidate[t]
output[t] = state[t] × gate[t]
```
- `alpha[t]` (forget factor): learned from the input itself — if alpha ≈ 1, keep past state; if alpha ≈ 0, reset and use new candidate
- `candidate[t]`: new information to potentially store
- `gate[t]`: learned output filter

**Bidirectional = Forward + Backward:**
```python
forward = SelectiveSSMMixer(sequence)       # processes left→right
backward = SelectiveSSMMixer(reverse(sequence))  # processes right→left, then reversed
output = fuse(concat([forward, backward]))
```
This lets each token see **full context** — both what came before AND what comes after — giving it a much richer understanding of the clip.

**Why Mamba over Transformer self-attention?**
- Transformers have O(N²) complexity in sequence length. For sequences of 384 or 512 tokens, that's expensive.
- Mamba has O(N) complexity — linear scaling. Much faster for long sequences.
- The selective gating is actually more powerful than fixed attention for sequential patterns.

#### Step 5: MutualCrossAttentionBlock

After each BiMambaBlock layer, the spectral and temporal streams talk to each other:

```python
# Spectral stream asks: "What temporal patterns should I pay attention to?"
spectral = spectral + MultiHeadAttention(
    query=spectral,       # "What do I want to know?"
    key=temporal,         # "What index into temporal info?"
    value=temporal,       # "What actual temporal info to absorb?"
)

# Temporal stream asks: "What spectral patterns should I pay attention to?"
temporal = temporal + MultiHeadAttention(
    query=temporal,
    key=spectral,
    value=spectral,
)
```

**Multi-Head Attention** with 4 heads means 4 different "aspects" are attended to simultaneously (e.g., head 1 might focus on low-frequency changes, head 2 on high-frequency, etc.).

This cross-attention runs **3 times** (depth=3), with BiMamba blocks in between. Each iteration, the two streams become more informed about each other. By the end, the spectral stream knows which time intervals had suspicious patterns, and the temporal stream knows which frequency bands were anomalous.

#### Step 6: Sequence Pooling and Final Classification

Three information streams are extracted and fused:
```python
spectral_features = concat([GlobalAvgPool(spectral), GlobalMaxPool(spectral)])   # (96+96 = 192)
temporal_features = concat([GlobalAvgPool(temporal), GlobalMaxPool(temporal)])   # (192)
map_features = GlobalAvgPool2D(feature_map)                                       # (96)

x = concat([spectral_features, temporal_features, map_features])                  # (480)
x → LayerNorm → Dense(384, gelu) → Dropout → Dense(128, gelu) → Dropout → Dense(1, sigmoid)
```

Using **both** `GlobalAvgPool` and `GlobalMaxPool`:
- **Avg Pool**: average behavior across the sequence (general tendency)
- **Max Pool**: peak response (captures strongest/most extreme pattern found anywhere)
- Concatenating both gives the final classifier richer information

**Total params: ~2.9M** (vs 943K for CNN) — this model is more expressive but needs more data to train well.

## 9. The Training Loop

### What is a Training Epoch?
One **epoch** = the model sees every training sample exactly once.
- 3,557 training samples ÷ 64 (batch size) = **~55 steps per epoch**
- Each step: load a batch → forward pass → compute loss → backprop → update weights

### Forward Pass
Data flows through the model, layer by layer, producing a prediction `ŷ` (e.g., 0.73 = "73% likely fake").

### Loss Function
**Binary Cross-Entropy:**
```
L = -[y × log(ŷ) + (1-y) × log(1-ŷ)]
```
- If `y=1` (truly fake) and `ŷ=0.95` → `L = -log(0.95) ≈ 0.05` (small loss, good prediction)
- If `y=1` and `ŷ=0.05` → `L = -log(0.05) ≈ 3.0` (large loss, very wrong prediction)
- Averaged over all 64 samples in the batch.

### Backpropagation
The loss gradient is computed and propagated backward through every layer using the **chain rule**. Each weight in each layer receives a small update signal: "move in this direction to reduce the loss."

### Optimizer: Adam (CNN) / AdamW (BiCrossMamba-ST)
**Adam** (Adaptive Moment Estimation) tracks:
- `m_t`: running average of gradients (momentum — keeps moving in same direction)
- `v_t`: running average of squared gradients (adaptive learning rate — larger steps for rarely-updated weights, smaller for frequently-updated)

**AdamW** = Adam + **Weight Decay** (L2 regularization):
```
weight_new = weight_old - lr × gradient - λ × weight_old
```
The `λ × weight_old` term gently pushes all weights toward zero, preventing any single weight from becoming excessively large (a form of regularization). `weight_decay=1e-4` in your BiCrossMamba-ST optimizer.

**`clipnorm=1.0`** in BiCrossMamba-ST: If the gradient norm exceeds 1.0, all gradients are scaled down proportionally. This prevents **exploding gradients** which can destabilize training in deep networks with recurrent connections.

## 10. Loss Functions, Optimizers, and Metrics

### Why Binary Cross-Entropy?
This is the standard loss for binary classification. It directly optimizes the **probability output** (sigmoid). Mean Squared Error would also work mathematically but converges much slower for classification tasks.

### The Four Metrics

| Metric | Formula | What it means for your task |
|---|---|---|
| **Accuracy** | (TP+TN) / Total | % of clips correctly labeled |
| **Precision** | TP / (TP+FP) | Of clips we CALLED fake, what % were actually fake? |
| **Recall** | TP / (TP+FN) | Of actually fake clips, what % did we catch? |
| **AUC** | Area under ROC curve | Overall discrimination ability, threshold-independent |

Where: TP=True Positive (correctly caught fake), FP=False Positive (wrongly flagged real as fake), FN=False Negative (missed a fake), TN=True Negative (correctly cleared real).

### Why do we monitor `val_auc` for checkpointing (not `val_accuracy`)?
**AUC is threshold-independent.** Accuracy depends on a chosen decision threshold (default 0.5). A model that outputs 0.55 for all fakes and 0.45 for all reals would have terrible accuracy but a good AUC. AUC measures how well the model *ranks* fakes above reals, regardless of the exact output values. It is a more robust measure of model quality.

### Class Weights
```python
class_weights = {0: 0.978, 1: 1.023}  # nearly balanced
```
Even though your dataset is nearly balanced (51/49), we still compute and apply class weights. During backpropagation, losses from class 1 (fake) are multiplied by 1.023 and class 0 (real) by 0.978. This makes the model pay slightly more attention to any remaining imbalance. If classes were severely imbalanced (say 90/10), these weights would be 0.55 and 4.5 — dramatically changing training.

## 11. Callbacks: How the Model Protects Itself

Your `main.py` uses three callbacks — these are functions called at the end of each epoch to make intelligent decisions.

### `ModelCheckpoint`
```python
monitor="val_auc", mode="max", save_best_only=True
```
Saves the model weights to disk **only when `val_auc` improves**. After 30 epochs, you end up with the weights from the single best epoch — not the last epoch (which might have overfit). This is critical.

### `EarlyStopping`
```python
monitor="val_auc", patience=5, restore_best_weights=True
```
If `val_auc` does not improve for **5 consecutive epochs**, training stops automatically. Then `restore_best_weights=True` resets the model back to the weights from the best epoch. This prevents:
- Wasting compute on a model that has already peaked
- **Overfitting**: when training accuracy keeps improving but val accuracy degrades

### `ReduceLROnPlateau`
```python
monitor="val_loss", factor=0.5, patience=2, min_lr=1e-6
```
If `val_loss` doesn't improve for **2 epochs**, the learning rate is halved (`factor=0.5`). Learning rate starts at `0.001`. After 2 plateaus → `0.0005`. After 4 → `0.00025`. Minimum is `0.000001`.

The intuition: when the model is stuck, take **smaller steps** to fine-tune rather than overshooting the optimal weights. This is analogous to walking quickly toward a target but slowing down as you get close.

## 12. Common Problems and What They Mean

### Val Accuracy Stuck at 0.4888, Val Recall = 1.0
This is a classic sign of a **trivial classifier** — the model is predicting *everything* as Fake (class 1).
- Precision: 0.4888 = exactly the fraction of fakes in the validation set
- Recall: 1.0 = it catches every fake (because it calls everything fake)
- AUC: 0.80 = but this is actually OK! AUC doesn't care about threshold

**Why does this happen at Epoch 1?** The model hasn't learned yet. Binary cross-entropy with a near-balanced dataset and random weights often initially trends toward predicting the majority class. By Epoch 2 the model was already recovering (val_acc jumped back to whatever it was).

**If it persists past Epoch 5**, the model may be stuck in this trivial minimum. Solutions: lower learning rate, add more regularization, check preprocessing.

### Bus Error on Mac
As discussed: memory pressure from TensorFlow Metal. The Metal GPU plugin for Apple Silicon has known stability issues under sustained memory load. Training on Colab's T4 GPU is the correct solution.

### "Allocation exceeds 10% of free system memory" on Colab CPU
You saw this in your Colab log. It means the model/batch is too large for Colab's RAM when running on CPU. The fix: **enable the T4 GPU**. On GPU, each batch resides in GPU VRAM (15 GB on T4), completely separate from system RAM.

### `val_auc` Worse than `train_auc` by Large Margin = Overfitting
If train AUC is 0.99 but val AUC is 0.72, the model has memorized the training data. Solutions:
- More Dropout
- More data (augmentation: time shift, pitch shift, add noise)
- Smaller model
- Early stopping (already set up)

### Very High Val AUC but Low Val Accuracy
This is actually fine at the beginning of training. It means the model is learning to rank correctly but the decision boundary (at 0.5 threshold) hasn't settled yet. As training continues, accuracy catches up.
